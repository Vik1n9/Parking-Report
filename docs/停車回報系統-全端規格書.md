# 停車回報系統（Parking Report）全端規格書

| 項目 | 內容 |
|---|---|
| 版本 | 0.1（草案，供研究） |
| 日期 | 2026-09-08 |
| 倉庫 | https://github.com/Vik1n9/Parking-Report |
| 現況 | 純前端（`index.html` 中控、`guard.html` 保全、`parking-core.js` 共用邏輯）；資料僅存瀏覽器 `localStorage` |
| 目標平台 | Cloudflare（Workers／D1 等） |

---

## 1. 背景與問題

現有工具能把現場停車狀態轉成：

- 中控口播文字
- Excel Tab 分隔列
- 保全 LINE 群組回報文字

但沒有後端，導致：

- 歷史無法跨裝置／跨人同步（清瀏覽器就沒了）
- 保全、中控、秘書各自複製貼上，流程斷裂
- 區域名稱與欄位順序寫死在程式裡，擴充困難

有 Cloudflare 後，應把三角色工作收斂到同一條可稽核的資料流。

---

## 2. 使用者與成功標準

### 2.1 保全（現場）

- **情境**：戶外強光、可能單手操作手機；清點各區後回報中控。
- **成功**：用最少視線轉移、最少捲動、最少打字完成固定區域回報並送出；弱網時不丟單。

### 2.2 中控

- **情境**：接收現場回報，轉成 LINE 工作群組文字，並寫入系統正式紀錄。
- **成功**：有待處理佇列；一鍵預覽／複製（或推送）LINE 文；確認後入庫；可修正並留稽核。

### 2.3 秘書助理

- **情境**：開啟系統紀錄，彙整主管會議報告。
- **成功**：依日期／班次查詢；一鍵匯出會議用摘要（CSV／可列印頁）；不必再從 LINE 截圖拼貼。

### 2.4 產品個性（沿用 PRODUCT.md）

清楚、直接、可靠。像現場工具，不像展示頁。強光優先、單手優先、首屏優先、防誤觸、現場語言（全滿、未停車、台車、LINE 回報）。

---

## 3. 目標流程

```
保全現場錄入
  → 建立「回報單」（pending）
    → 中控審核／可改數字
      → 確認入庫（confirmed）＋產出 LINE／口播／Excel 快照
        → 秘書依區間彙整會議報告
```

狀態機：`draft`（本機未送）→ `pending` → `confirmed`（可 `rejected` 退回保全）。

---

## 4. 前端資訊架構

同一站、權限分流（建議路徑）：

| 角色 | 路徑 | 說明 |
|---|---|---|
| 保全 | `/guard` | 沿用現有強光／內建數字鍵盤／固定格序 UX |
| 中控 | `/control` | 待處理佇列＋口播／LINE／Excel 預覽＋確認入庫 |
| 秘書 | `/reports` | 查詢正式紀錄、匯出會議摘要 |
| （可選）設定 | `/settings` | 區域／班次設定（P2） |

**認證（建議漸進）**

- P0：Cloudflare Access（公司信箱）或角色邀請碼／magic link
- 保全可綁「班別＋裝置」
- 不做過重的自建帳密系統

---

## 5. 後端架構（Cloudflare）

| 層 | 選型 | 用途 |
|---|---|---|
| 運算 | Workers（或 Pages + Functions／vinext） | API＋前端託管 |
| 資料 | D1 | 回報單、正式紀錄、區域、角色 |
| 即時 | 短輪詢或 Durable Object（可選） | 中控「有新回報」 |
| 檔案 | R2（可選） | 會議匯出檔／PDF |
| 機密 | Workers Secrets | LINE token、Access 相關 |
| 排程 | Cron Triggers | 日彙總、清過期草稿 |

**關鍵約束**：`parking-core.js`（解析、zoneInfo、buildLineReport、buildControlReport、buildExcelValues）必須是**唯一格式化來源**，前端顯示與 Worker 入庫共用，禁止三端各寫一套文案邏輯。

參考實作經驗：與 `twstock-gacha` 相同技術棧方向（Workers＋D1），但本系統流量低、寫入量小，Free／Paid 壓力遠低於抽卡站。

## 6. 領域與現有輸入規則（須相容）

### 6.1 預設 10 區順序（現況 hardcoded）

1. 一樓以上  
2. 一樓以下  
3. P1  
4. P3  
5. 紡A  
6. 紡B  
7. 紡C  
8. 紡D  
9. 紡E  
10. 柏油路  

### 6.2 數值語意

| 區域類型 | 整數意義 |
|---|---|
| IS_CAR（一樓以上、一樓以下） | 剩餘車位數 |
| 非 IS_CAR（其餘） | 成數（如 `8`＝尚有 8 成） |

| 輸入 | 意義 |
|---|---|
| `0` | 全滿 |
| `x` | 未停車／未啟用 |
| `0.1`～`0.9` | 台車數（小數點後＝台數） |
| `A`～`E`、`R` | 別名（紡A～E、柏油路） |
| `key=value` | 具名指定，可與位置 token 混用 |

塔樓利用率：以一樓以上＋一樓以下剩餘車位與 `TOWER_TOTAL`（現況 1600）計算。

P0 可先把上述常數 **seed 進 D1**；P2 再做成可設定後台。

## 7. 資料模型

### 7.1 `sites`（可選，多廠區）

- `id`, `name`, …

### 7.2 `zones`

- `id`, `site_id`, `sort_order`, `label`, `alias`, `is_car`（bool）, `active`

### 7.3 `shifts`

- `id`, `name`（日／夜等）, `start_time`, `end_time`

### 7.4 `users`

- `id`, `display_name`, `role` ∈ `guard | control | secretary`, `auth_subject`

### 7.5 `reports`（待審／草稿流）

- `id`
- `site_id`, `shift_id`（可空）
- `status` ∈ `pending | rejected`
- `tokens_json`（長度＝區數）
- `raw_input`
- `submitted_by`, `submitted_at`
- `reject_reason`（可空）

### 7.6 `records`（正式）

- `id`, `report_id`（可空，若中控直接建）
- `site_id`, `shift_id`
- `tokens_json`, `raw_input`
- `line_text_snapshot`, `control_text_snapshot`, `excel_row_snapshot`
- `tower_util_pct`（可空，冗餘方便查詢）
- `confirmed_by`, `confirmed_at`

### 7.7 `audit_log`

- `id`, `entity_type`, `entity_id`, `actor_id`, `action`, `before_json`, `after_json`, `at`

## 8. API 草圖

| 方法 | 路徑 | 說明 | 角色 |
|---|---|---|---|
| POST | `/api/reports` | 保全送出回報單 | guard |
| GET | `/api/reports?status=pending` | 中控佇列 | control |
| POST | `/api/reports/:id/confirm` | 確認入正式庫；回傳三種文案 | control |
| POST | `/api/reports/:id/reject` | 退回 | control |
| GET | `/api/records?from=&to=&shift=` | 秘書／中控查詢 | control, secretary |
| GET | `/api/records/export?from=&to=&format=csv\|md` | 會議匯出 | secretary |
| GET | `/api/zones` | 區域設定 | 登入者 |

所有寫入需驗證角色；確認時由伺服器用 `parking-core` 重算快照後再存，前端預覽可與伺服器校驗一致。

## 9. LINE 整合策略

### 階段 A（MVP，建議第一版）

- 中控確認後，UI 提供「複製 LINE 回報」「分享」
- 文案以 `records.line_text_snapshot` 為準
- 人員仍在 LINE App 內選群組送出（合規單純、實作快）

### 階段 B（進階）

- LINE Messaging API 推到指定群組
- Secrets 存 Channel access token
- 失敗則 fallback 到複製／分享

秘書流程**不依賴** LINE，只讀 `records`。

---

## 10. 秘書會議報告

匯出至少包含：

1. 區間內各班次／時間點的正式回報列表  
2. 塔樓利用率摘要（若有）  
3. 各區「全滿／未停車」次數統計  
4. 異常：退回件、逾時未報（若有 SLA）、與上一筆差異過大（規則可設定）

格式：

- `csv`：給 Excel  
- `md` 或列印友善 HTML：給主管會議

## 11. 非功能需求

| 項目 | 要求 |
|---|---|
| 行動保全 UX | 維持 PRODUCT.md：強光、大按鈕、單手、少捲動 |
| 弱網 | 保全端可本機佇列，恢復後重送（冪等：client_request_id） |
| 稽核 | 中控改數字必須寫 `audit_log` |
| 隱私 | 正式環境勿公開 GitHub Pages 無驗證；改 Access 保護 |
| 測試 | 既有 `parking-core.test.js`／`guard-ui.test.js` 繼續；新增 API 整合測 |
| 觀測 | Workers Logs；關鍵錯誤（入庫失敗）可查 |

## 12. 與現有程式的關係

| 現有資產 | 處理方式 |
|---|---|
| `guard.html` | 演進為 `/guard`；送出改打 API，不只寫 localStorage |
| `index.html` | 演進為 `/control`；加佇列與確認 |
| `parking-core.js` | 抽成共用模組（前端＋Worker） |
| localStorage 歷史 | 降級為離線快取／草稿，不再是唯一真相 |
| GitHub Pages 靜態站 | 遷移至 Workers／Pages 部署 |

## 13. 分階段里程碑

### P0 — MVP（建議 1～2 週可研究／試作）

- Workers＋D1  
- 保全送出、中控確認入庫、跨裝置歷史  
- LINE 維持手動複製／分享  
- 區域以 seed 現有 10 區  

### P1

- 秘書匯出（CSV／會議摘要）  
- 中控待辦即時感（輪詢即可）  
- 稽核軌跡、弱網佇列  

### P2

- 區域／班次設定後台  
- LINE Bot 一鍵推播  
- 多廠區
